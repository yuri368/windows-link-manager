# Windows Link Manager

**软件和数据留在原来的磁盘，重装 Windows 后，把它们需要的文件夹、文件路径重新接起来。**

适用于 Windows 10 / 11 · 中文图形界面 · 安装版 / 便携版 · 开源免费

[**⬇️ 下载 v2.0.1**](https://github.com/yuri368/windows-link-manager/releases/tag/v2.0.1) · [三步上手](#三步上手) · [配置示例](examples/软链接.example.txt) · [反馈问题](https://github.com/yuri368/windows-link-manager/issues)

## 这是什么？为什么要用它？

你有没有遇到过这些情况？

- **经常重装 Windows**：软件和游戏还在 D 盘、H 盘，但新系统里原来的文件夹位置、配置目录或数据入口都没了。
- **有好几个 Windows 系统**：希望不同系统都能使用另一块硬盘里的同一份应用数据，却不想每次手动重建文件夹链接。
- **想把数据挪出 C 盘**：软件偏偏只认某个固定目录，直接移动文件夹后，它就找不到东西了。
- **链接创建过不少**：时间一长，忘了哪个链接属于哪个应用，更不知道重装系统后要重新创建哪些。

**Windows Link Manager 就是用来管理这些“路径连接”的。**

你可以把一个应用需要的多个链接放在同一个项目里，保存下来。需要时检查、预览并批量创建，不必重新查找每条路径，更不需要把所有命令再敲一遍。

它不负责安装或搬运软件，也不会自动让所有 Windows 软件变成便携版。它解决的是其中一个重要问题：**让应用能通过熟悉的路径，访问原来位置的文件和数据。**

## 它是怎么工作的？

可以把链接理解成：**在应用熟悉的位置，放一个通往真实文件或文件夹的入口。**

例如，一款示例软件希望从 C 盘读取数据，但实际数据存放在 H 盘：

```text
真实数据（源路径）
H:\MyApps\ExampleApp\Data
              │
              │ 创建目录链接
              ▼
软件访问的位置（目标路径）
C:\Users\你的用户名\AppData\Roaming\ExampleApp\Data
```

创建合适的链接后，软件仍访问原来的 C 盘路径，而数据可以保留在 H 盘。

**这里不是复制一份文件。** 对目录联接点和目录符号链接来说，链接路径是访问真实目录的另一个入口。具体能否正常使用，还要看软件自身的要求。

> **路径方向很重要**：在本工具中，**源路径**是已经存在的真实文件或文件夹；**目标路径**是准备放置链接、供软件访问的位置。创建前请仔细核对，尤其是目标位置已有文件时。

## 为什么不直接用 Windows 的 mklink？

Windows 自带的 `mklink`、[Symlinker](https://github.com/amd989/symlinker) 等工具已经能创建文件链接。**创建链接本身并不是本项目独有的功能。**

Windows Link Manager 更侧重 **“把需要的链接长期整理好，之后还能重新创建”**：

| 常见麻烦 | Windows Link Manager 的做法 |
| --- | --- |
| 每次都要重新输入源路径、目标路径 | **保存链接配置**，下次可以继续使用 |
| 一个应用需要好几个链接 | **按项目分组**，把相关链接放在一起 |
| 重装系统后要重新建一批链接 | **批量选择、检查、预览和创建**，避免一个个敲命令 |
| 担心目标位置本来就有文件 | **默认保护已有普通文件和目录**，不会直接覆盖 |
| 有些路径确实需要替换 | 提供**先备份再替换**的处理方式，并记录操作 |
| 不清楚刚才改了什么 | **操作历史与恢复检查**，在满足安全条件时可撤销创建操作 |

这个定位尤其适合**经常重装系统、多 Windows 用户，以及把软件和数据长期保存在非系统盘的人**。

## 三步上手

### 第一步：下载安装，或者解压即用

从 [v2.0.1 发布页面](https://github.com/yuri368/windows-link-manager/releases/tag/v2.0.1) 选择一种：

| 版本 | 应该下载哪个？ | 如何启动？ |
| --- | --- | --- |
| **安装版（推荐）** | `windows-link-manager-2.0.1-windows-x64-setup.exe` | 双击安装，从开始菜单打开 |
| **便携版** | `windows-link-manager-2.0.1-windows-x64.zip` | 解压后运行 `WindowsLinkManager.exe` |

**不需要另装 Python、Qt，不需要运行命令，也不需要联网安装运行依赖。**

支持 **Windows 10 1809 及更新版本 / Windows 11 x64**。安装程序默认装在当前用户目录，安装本身不需要管理员权限。

便携版请保留 `WindowsLinkManager.exe` 旁边的 `_internal` 文件夹，不要只复制一个 EXE。

### 第二步：为应用添加链接

首次打开是空列表，可以点击 **“新增”**：

1. 给链接选择或创建一个项目，例如“常用软件”“游戏存档”“开发工具”。
2. 填入**源路径**：真实数据当前所在的位置。
3. 填入**目标路径**：希望软件通过哪个位置访问数据。
4. 选择链接类型；普通的文件夹路径映射可以先了解默认的 **Junction（目录联接点）**。
5. 保存配置。可以继续给同一项目添加其他链接。

保存只会记录配置，**不会立刻修改磁盘上的文件和目录**。

### 第三步：预览，再创建

选择要操作的记录，先检查状态，再点击 **“预览并创建”**。

工具会展示准备执行的操作，并检查路径是否冲突。确认没问题后才创建链接。发现目标位置被普通文件或文件夹占用时，默认会阻止覆盖。

**第一次使用建议先拿测试文件夹尝试，不要直接对重要存档、系统目录或唯一一份数据操作。**

## 哪些场景最值得用？

**💻 重装系统后恢复软件需要的路径**

软件和数据都保存在 H 盘，旧 Windows 中的链接却随着 C 盘重装消失了。你可以提前备份链接配置，重装后重新检查并创建这些入口，而不必凭记忆逐个恢复。

**🖥️ 多个 Windows 共用应用文件**

同一块数据盘被多个 Windows 系统使用。你可以在各个系统里使用同一份链接配置，核对路径后分别创建链接。**这不是自动跨系统同步，也不会让正在使用的两个系统自动协调数据。**

**📁 让数据留在非系统盘**

有些程序习惯读写固定目录。若适用，可以把真实数据放到另一块磁盘，再用链接提供它期望访问的路径，减少 C 盘数据堆积。

**🎮 整理游戏存档、工具配置和开发目录**

把相同应用或同一套工具涉及的目录链接归到一个项目。以后要重建或检查，不用在一长串不相关路径中寻找。

## 主要功能

- **按项目管理**：分组、搜索、批量选择；每条链接都能新增、编辑或删除配置。
- **支持多种链接**：目录联接点（Junction）、目录符号链接、文件符号链接、文件硬链接。
- **先检查再操作**：执行前展示计划，检查源路径、目标路径和危险的路径关系。
- **保护已有数据**：默认不覆盖普通文件或目录；可以选择先备份再替换。
- **历史记录与恢复检查**：保留操作历史，满足条件的创建记录可撤销；不确定的情况会提示人工检查。
- **配置可保存、导入和导出**：适合日后重建一组链接。
- **清爽的桌面界面**：浅色 / 深色外观，可搜索，也可以调整表格列宽。

## 四种链接应该选哪个？

不用死记 Windows 命令，先理解用途：

| 类型 | 适合什么 |
| --- | --- |
| **目录联接点（Junction）** | 常见的本机文件夹路径映射，适合许多应用数据目录 |
| **目录符号链接** | 给文件夹创建另一条访问路径；可能需要开发者模式或相应权限 |
| **文件符号链接** | 给单个文件创建路径入口；可能需要开发者模式或相应权限 |
| **文件硬链接** | 两个文件名指向同一份文件内容，**必须在同一个磁盘卷** |

**不确定时：** 如果只是要让软件从固定位置找到另一个本机文件夹，可以先了解 Junction 是否适用。不同类型并非完全等价，尤其不要把硬链接当成普通的文件快捷方式。

## ⚠️ 关于覆盖、备份和撤销

管理文件链接会接触真实路径，这部分值得认真看：

| 目标位置已有东西时 | 会发生什么 |
| --- | --- |
| **保护普通目标（默认）** | 停止创建，不直接覆盖原来的文件或文件夹 |
| **备份后替换** | 先把原目标移到旁边的备份位置，再尝试创建链接；出错时会尝试恢复 |
| **永久删除后创建** | **永久删除原目标的数据，再创建链接**。不会进入回收站、没有备份，**无法撤销删除的数据** |

“仅移除链接”只移除链接入口，不会沿着目录链接去清空它指向的源目录。

不过，**撤销不等于无限制的时光倒流**。工具需要确认链接和备份仍符合原来的状态，才能执行安全的撤销或恢复。如果目标被其他程序修改、状态不确定或权限不足，可能停止并要求你人工处理。

符号链接可能需要 Windows 开发者模式或相应权限；程序不会自动开启开发者模式或强制获取管理员权限。

## 重装 Windows 后怎么恢复？

这是本项目最想解决的使用场景之一：

1. **旧系统：** 把应用需要的链接整理为项目，保存配置。
2. **重装前：** 备份 `软链接.txt`；如果希望保留操作记录，也备份 `.state`。最好放在不会随系统重装被清除的位置。
3. **新系统：** 安装或解压 Windows Link Manager，恢复配置。
4. **核对路径：** 确认源数据仍在、目标位置正确，而且没有意外占用。
5. **重新创建：** 选择需要的项目或链接，查看操作预览，确认后执行。

安装版和便携版的程序运行数据保存在**程序所在目录**，常见文件是：

```text
Windows Link Manager/
├─ WindowsLinkManager.exe
├─ 软链接.txt        ← 你的链接配置
└─ .state/           ← 操作历史等运行数据
```

安装版升级或卸载时会保留个人创建的配置和历史，但重装 Windows 或删除整个程序目录前，仍应**手动备份**。便携版迁移则应复制完整程序目录（包括 `_internal`、配置及历史）。

> 链接配置只记录路径关系，**不是源文件的备份**。如果 H 盘里的原始数据已经丢失，单靠重新创建链接无法恢复它。

## 想自己保存一份链接清单？

一般用户在 GUI 里新增和编辑就好。配置是简单的 UTF-8 文本文件，也可以手动维护：

```text
【示例软件】
H:\MyApps\ExampleApp\Data
C:\ExampleApp\Data

# @type=file_symlink
H:\MyApps\ExampleApp\settings.ini
C:\ExampleApp\settings.ini
```

每组路径按照 **源路径在前，目标路径在后** 的顺序填写。`【示例软件】` 是项目名；没有指定类型时，默认创建目录联接点。上面的路径只是示范，不要未经修改就拿来执行。

可以从 [官方配置模板](examples/软链接.example.txt) 开始修改。保存已有配置时，程序也会在配置旁的 `.backups` 目录保留旧文本备份。

## 和 Windows 环境变量方案管理器一起使用

同一作者还有一个项目：[**Windows 环境变量方案管理器 V2**](https://github.com/yuri368/windows-environment-manager-v2)。

两款工具解决的是应用恢复过程中不同的问题：

| 工具 | 主要负责 |
| --- | --- |
| **Windows Link Manager** | 恢复应用需要的**文件、文件夹路径入口** |
| **Windows 环境变量方案管理器 V2** | 恢复应用需要的 **Path、JAVA_HOME 等环境变量** |

例如，软件文件原本就在 H 盘；在新 Windows 中，可以分别重建它需要的目录链接和环境变量，让应用更容易恢复到可用状态。

**两者完全独立，不会自动联动。** 软件本身如还依赖注册表、服务、驱动或其他系统组件，仍需要另外处理。

## 常见问题

**Q：这是创建 Windows 快捷方式（.lnk）的软件吗？**

不是。它管理的是文件系统链接，包括 Junction、符号链接和硬链接，和桌面上的 `.lnk` 快捷方式不是同一回事。

**Q：保存链接配置后，会马上修改文件吗？**

不会。保存是保存记录；只有执行预览、确认创建等操作时，才会尝试修改实际文件系统。

**Q：把 C 盘目录链接到 H 盘，会把文件自动搬过去吗？**

不会。你需要先确保真实数据已经在正确的源路径。本工具不负责自动搬运文件。

**Q：旧 Windows 没了，链接还能恢复吗？**

只要配置已备份、真实源数据仍然存在、目标路径可用，并满足 Windows 的权限和文件系统要求，就可以尝试重新创建。

**Q：卸载软件会删除我的源数据吗？**

卸载管理器与删除你所链接的源数据是两回事。卸载程序不会主动清理链接的源数据；但请不要把卸载管理器理解为自动删除或还原所有已创建的链接。

## 开发者说明

普通用户无需安装 Python 或运行以下命令。

源码版本需要 **Python 3.11–3.14（64 位）**。可从源码目录双击 `启动.cmd` 或 `启动.vbs`，首次启动会创建虚拟环境并安装所需依赖；也可运行 `python -m linkmanager`。
